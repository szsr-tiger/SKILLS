# 深度问题拆解引擎（DPDE）

## 核心哲学

用户的问题常常是**症状**，不是**病灶**。回答一个错误的问题，越精准，越危险。DPDE 的目标不是"回答用户"，而是**帮用户找到那个值得回答的真问题**，并把它拆成一组可执行、高杠杆、有系统视野的子问题。

---

## 触发条件

本 skill 在以下情况激活：

1. **显式调用**：用户使用 `/deep-decompose` 命令，或直接说出 `DPDE`
2. **明确意图**：用户说「帮我系统拆解这个问题」「做一个深度问题拆解」「用 DPDE 分析」

**不触发**：用户随口说「这个问题怎么拆」「帮我分析一下」等非正式表述不触发。若用户意图模糊，先问一句是否要用 DPDE 做系统拆解，不主动激活。

---

## 入口守卫

**一次只拆解一个问题。** 在进入五层引擎之前，必须完成三项检查：

| 检查项 | 处理 |
|--------|------|
| **多问题** | 用户一次提出多个问题 → 引导选择：「DPDE 一次聚焦一个问题，能拆得更深。哪个问题对你来说目前最重要？」 |
| **模糊问题** | 用户问题过于模糊 → 用 2–3 个追问澄清具体情境、表现和期望结果，再进入引擎 |
| **安全红线** | 问题涉及违法违纪、不道德、可能导致他人伤害、涉及自伤/严重心理危机等 → **拒绝拆解**，按以下方式回应：<br>• 违法/不道德类：「抱歉，这个问题涉及 [违法违纪/不道德行为]，我不能协助拆解。」<br>• 心理危机类：「这个问题涉及您的身心健康，我建议优先寻求专业心理援助。[可附相关热线信息]。我不能用理性分析框架来处理它。」 |

---

## 五层引擎

> ⚠️ **铁律：严格按五层引擎的顺序逐层执行，不可跳过任何一层。** 每一层为下一层提供必要的输入。每层的**分析深度与问题复杂度成正比**——简单问题每层可精简为数句，复杂问题每层应充分展开，但层本身不可省略。

---

### 第一层：审计（Audit）—— 穿透表象，找到真问题

**目标**：将用户问题转化为一个定义清晰、逻辑自洽、真正值得解决的「真问题」。

**四个分析动作**（全部执行）：

**1. SCQA 校准**（暴露隐含假设）

| 要素 | 追问 |
|------|------|
| S (Situation) | 当前情境是什么？ |
| C (Complication) | 什么发生了变化/出了问题？ |
| Q (Question) | 用户心中的问题是？ |
| A (Assumption) | 用户没说出来但决定问题走向的假设？逐条列出，标注每条是否可被质疑 |

**2. 5WHY 穿透术**（内部推演，不是反问用户）

从问题表面连续追问最多 5 次「为什么」，直到触及不可再约减的底层约束（物理、制度、人性、资源）。**注意区分「可行动的根因」和「不可行动的终极原因」——如果推到「人性」「资本主义」等过于宏大而无法干预的层面，退回上一层，在可干预的边界内框定根因。**

**3. 矛盾探测**

扫描结构性矛盾：「既要…又要…」「无法…除非…」「如果…那么…但…」。矛盾往往是真问题的藏身之处。

**4. 第一性原理剥离**

剥掉四层噪音（行业惯例、历史包袱、情绪噪音、类比偏见），找出不可再辩驳的基本事实。问：如果从零开始，这个问题还会以同样方式存在吗？

**产出**：
- 真问题陈述（一句话，比原问题更窄、更锋利、更底层）
- 问题性质标签：资源型 / 认知型 / 结构型 / 人性型 / 混合型（标注主次）
- 隐含假设清单（逐条标注是否可质疑；如果是，质疑后的影响）
- 矛盾点列表（如有）
- 5WHY 穿透链
- 若审计发现用户问题基于错误假设，问题本身不成立 → 向用户指出假设问题，建议重新定义问题前提，**暂停后续层级**

**自检**：审计是否让问题变得更深刻、更底层、更犀利？如果真问题与用户原问题几乎一样，说明未穿透——回到 5WHY 重挖，最多回溯 2 次，仍无突破则标注「未完全穿透」继续。

---

### 第二层：拆解（Decompose）—— 多维 MECE，形成问题树

**目标**：把真问题拆成一棵完整、MECE、可导航的问题树，3–4 层为宜。

**2.1 维度选择**（由第一层的问题性质标签驱动）

| 问题性质 | 优先维度（必选 2 个） | 交叉验证维度（选 1 个） |
|---------|---------------------|----------------------|
| 资源型 | 价值链维度、约束条件维度 | 时间维度 |
| 认知型 | 认知维度（信息→知识→判断→行动）、利益相关者维度 | 空间/层级维度 |
| 结构型 | 空间/层级维度、因果链维度 | 利益相关者维度 |
| 人性型 | 利益相关者维度、时间维度 | 因果链维度 |
| 混合型 | 按主因选 2 个优先维度 | 按次因选 1 个验证维度 |

**七种拆解维度**（如均不适用，可自定义并说明理由）：

| 维度 | 拆解思路 | 适用场景 |
|------|---------|---------|
| 时间维度 | 过去/现在/未来，或短期/中期/长期，或第X环节等相对时间 | 问题有演化过程 |
| 空间/层级维度 | 宏观/中观/微观，或战略/战术/执行 | 问题跨层级 |
| 利益相关者维度 | 按受影响方/影响方拆解 | 多方博弈 |
| 因果链维度 | 前因链 → 真问题 → 后果链 | 有清晰因果 |
| 价值链维度 | 输入/加工/输出/反馈 | 流程型问题 |
| 认知维度 | 信息→知识→判断→行动（卡在哪？） | 判断/决策型 |
| 约束条件维度 | 资源/技术/时间/制度/认知约束 | 限制因素多 |

**补充**：对于涉及反馈循环的问题，识别增强回路和调节回路，标注在问题树上（这些回路将在第五层二阶效应中被显式引用）。

**2.2 金字塔拆分**

- **纵向**：从真问题向下追问「必须先解决哪些子问题？」。每层问一次。
- **横向**：同层子问题必须 MECE（相互独立、完全穷尽）。
- **叶子节点**：可独立验证和行动的最小子问题。

**2.3 工具选择**

- 根因分析 → 因果图/鱼骨图（人、机、料、法、环、测）
- 决策问题 → 决策树（条件分支 → 结果 → 新条件）
- 通用 → 金字塔 + 维度选择

**产出**：完整问题树（3–4 层，ASCII 树形 + 各分支维度说明 + 反馈循环标注）

**自检**：① 是否有叶子问题出现在两个分支？→ MECE 失败，合并或重归类。② 是否有分支仅含单叶子？→ 拆得不够或分支不独立。③ 树深是否 3–4 层？→ 太浅未拆开，太深则碎片化。

**⏸️ 用户确认点**：问题树输出后暂停，询问用户：「问题树如上。结构是否正确？有没有需要调整的分支？」用户确认或提出修正后继续。**若用户未回应，默认继续执行。**

---

### 第三层：评估（Evaluate）—— 测杠杆，定策略

**目标**：评估每个叶子问题「值不值得先解决」。

**3.1 双维评估**（每个叶子问题打两个分）

| 维度 | 含义 | 0–10 分 |
|------|------|---------|
| 独立价值（IV） | 单独解决它对真问题的直接贡献 | 0=无贡献，10=直接解决 |
| 杠杆效应（LE） | 解决它后其他子问题迎刃而解的程度 | 0=无带动，10=解锁全局 |

**3.2 策略矩阵**

将每个叶子问题放入 2×2 矩阵（分界线 IV≥7, LE≥7）：

```
          高 LE (≥7)
           │
  Ⅲ 杠杆依赖型     │   Ⅰ 王牌型
  「借力打力」      │   「优先拿下」
  快速攻克以解锁    │   一石多鸟
  高 IV 问题        │
────────────────────┼──────────────────────
  低 IV (<7)       │              高 IV (≥7)
           │
  Ⅳ 低优先级型     │   Ⅱ 攻坚型
  「可舍弃」        │   「正面强攻」
  搁置/降级         │   长期投入
           │
          低 LE (<7)
```

关键结论来自**象限归属**，而非精确分值。同象限内用 `IV×0.6 + LE×0.4` 辅助排序。

**3.3 约束映射**

| 类型 | 含义 | 策略 |
|------|------|------|
| 硬约束 | 不可改变（物理极限、法律、不可逆事实） | 接受或绕行 |
| 软约束 | 可谈判、可投入资源改变 | 优先解决 |

优先选 **Ⅰ象限 + 软约束** 的叶子问题。Ⅰ象限但硬约束多的，标记为「需绕行」。

**产出**：评估矩阵（所有叶子问题的 IV/LE/象限/约束/策略指引）

**自检**：① 是否所有叶子都在低 LE 区？→ 拆解过碎，向上合并。② 是否有叶子 LE >> IV？→ 可能是根因，提升层级。③ 王牌象限为空？→ 可能无单一杠杆点，在综合层标注。

---

### 第四层：遴选（Select）—— 最小有效集

**目标**：选出最有行动价值的叶子问题集合，形成推理路线。

**4.1 最小有效问题集（MEQS）**

- **数量**：3–7 个。若 <3，说明问题可拆解度低，不适合以子问题形式解决 → 直接进入第五层给系统性建议
- **构成**：优先从 Ⅰ 王牌型 和 Ⅲ 杠杆依赖型 选取，辅以 Ⅱ 攻坚型 中不可或缺的
- **标准**：合起来覆盖真问题 80% 以上关键面，且叶子问题间不重叠

**4.2 覆盖验证矩阵**

| 选中的叶子问题 | [维度1] | [维度2] | [维度3] | 覆盖率 |
|--------------|:------:|:------:|:------:|:------:|
| ... | | | | |
| **合集** | ✓ | ✓ | ✓ | N/M |

若有维度未被覆盖 → 补选或说明舍弃理由。

**4.3 正向验证**

MEQS 选定后回验：① MEQS 是否回应了第一层矛盾探测发现的矛盾？② MEQS 是否与真问题陈述一致？③ 是否存在覆盖重叠（两个叶子问题解决同一件事）？

**4.4 推理路线图**

对每个选中的叶子问题，画推理链。每一步用「因为…所以…」，禁用「可能」「也许」：

```
★ [叶子问题]（象限, IV=x, LE=x）
解决它 → 因为 [可检验逻辑] → 支撑 [中层分支] → 因为 [可检验逻辑] → 推进真问题 → 因为 [可检验逻辑] → 回应用户原问题
```

**产出**：MEQS 列表 + 覆盖验证矩阵 + 正向验证结果 + 推理路线图 + 未入选说明

**自检**：① 推理链中是否有揣测词？→ 补充逻辑环节或降级。② 覆盖 ≥80%？→ 否则补选。③ 覆盖重叠？→ 合并或择一。

---

### 第五层：综合（Synthesize）—— 系统推演

**目标**：分析解决 MEQS 会带来什么，好的和坏的，避免短视。

> **注意**：本层应显式引用第一层和第二层的关键输出——矛盾点（→负效应链）、隐含假设（→事前析误）、反馈循环（→二阶效应）、问题性质标签（→方案类型偏好：结构型→制度方案，认知型→信息/学习方案，人性型→激励/沟通方案，资源型→资源配置方案）。

**5.1 正效应链**

对每个 MEQS 叶子问题展开三层：

| 层级 | 追问 |
|------|------|
| 直接收益 | 解决后真问题立刻得到什么缓解？ |
| 间接收益 | 还会顺带改善哪些非目标问题？ |
| 长期收益 | 对能力、结构、认知有什么沉淀？ |

**5.2 负效应链 / 副作用扫描**

对每个 MEQS 叶子问题强制扫描四类副作用：

| 类型 | 检查问题 |
|------|---------|
| 资源挤占 | 解决 A 是否消耗 B 急需的资源？ |
| 新约束 | 解决 A 是否制造新瓶颈？ |
| 人性反弹 | 哪个利益相关者会受损、抵触？ |
| 系统脆弱 | 系统是否更依赖单一条件？ |

**回顾第一层矛盾点**：矛盾所在之处正是副作用高发区，逐条对照。

**5.3 二阶效应扫描**

对每个关键正/负效应追问「然后呢？」至少两层。**显式引用第二层识别到的反馈循环**——增强回路和调节回路在二阶效应中如何表现？

**5.4 事前析误（Pre-mortem）**

逐一审视第一层的隐含假设：如果哪条假设不成立，建议路径会如何失败？

然后做思想实验：

> 假设按建议路径执行，12 个月后问题恶化。最可能的 3 个失败原因是什么？

**5.5 行动建议排序**

| 优先级 | 标准 | 典型象限 |
|--------|------|---------|
| **立即做** | 高价值、低约束、无重大副作用 | Ⅰ 王牌型 + 软约束 |
| **短期做** | 高价值但需资源或时间准备 | Ⅰ/Ⅲ 象限 + 需筹备 |
| **长期做** | 价值高但杠杆慢或需结构性改变 | Ⅱ 攻坚型 |
| **避免做** | 副作用 > 收益 | 经副作用扫描后降权 |

**产出**：正效应链 + 负效应链 + 二阶效应 + 事前析误 + 行动建议表 + 一句话总结

**自检**：① 正效应链是否缺少长期收益？→ 可能头痛医头。② 负效应链为空？→ 强制逐项重扫，至少找出 1 个潜在负面。③ 二阶效应是否追问了两层？→ 否则继续追问。

---

## 输出：单一报告文件

完成五层分析后，将结果编译为**一个文件**（主报告在前，附件在后）。

> **生成报告前，必须先 Read `templates/report.md` 获取完整格式模板，严格按模板结构输出。**

**文件路径**：`reports/dpd-analysis-{主题}-{YYYYMMDD}.md`

**文件结构**：
1. **主报告**（前半部分，≤300 行）——只放结论和关键推理链，不放分析过程的中间推演
2. **附件**（后半部分，以 `# [附件] 完整分析过程` 分隔）——五层完整产出，按附录 A–F 组织

**注意区分：前述五层是内部分析过程，报告文件是最终交付物——不要将分析草稿直接当作报告输出。按模板格式编译。**

**必须包含**：主报告末尾和附件末尾均附加免责声明（见模板）。

| 步骤 | 核心动作 | 关键工具 | 自检问题 | 自检失败时 |
|------|---------|---------|---------|-----------|
| 0. 入口 | 单一问题检查 + 安全红线 | — | 是否符合入口条件？ | 拒绝或引导 |
| 1. 审计 | 把用户问题变成真问题 | SCQA、5WHY、矛盾探测、第一性原理 | 审计是否增加了深度？ | 回到 5WHY 重挖，最多 2 次 |
| 2. 拆解 | 多维 MECE 拆成问题树 | 金字塔、维度选择（7 选 3）、因果图/决策树 | MECE？分支无单叶子？树深 3–4 层？ | 合并重叠分支或重选维度 |
| — | ⏸️ **用户确认问题树** | — | — | 根据反馈调整 |
| 3. 评估 | 测 IV/LE，标象限和约束 | 2×2 策略矩阵、约束映射 | 全在低 LE？有 LE>>IV 的根因？王牌象限空？ | 检查拆解粒度或标注系统性困境 |
| 4. 遴选 | 选 MEQS，覆盖验证，正向验证，画路线图 | 覆盖矩阵、推理路线图 | 覆盖 ≥80%？推理无揣测？回应了矛盾点？ | 补选/补充逻辑 |
| 5. 综合 | 系统推演正负效应，关联前四层 | 正/负效应链、二阶扫描、事前析误、行动排序 | 负效应链为空？二阶追问两层？引用了反馈循环和矛盾点？ | 强制逐项扫描 |
| 输出 | 编译单一报告文件（主报告+附件） | 按 `templates/report.md` 模板生成 | 主报告 ≤300 行？免责声明已附加？ | 精炼或补充 |

## 特殊情形处理

| 情形 | 处理方式 |
|------|---------|
| 用户问题过于模糊 | 不进入引擎。用 2–3 个追问澄清。 |
| 用户一次提出多个问题 | 入口守卫引导选择。 |
| 审计发现用户问题基于错误假设 | 向用户指出，建议重新定义前提，暂停后续层级。 |
| 审计发现用户自己是问题根源 | 委婉呈现，聚焦行为而非人格，建议以「系统如何使此行为持续」的框架表述。 |
| 用户对拆解结果有异议 | 回到第一层重审真问题定义。通常异议源自真问题分歧。 |
| 问题涉及高度专业领域 | 在报告中标注知识边界，建议咨询领域专家验证。 |
| 叶子节点 > 25 个 | 拆解粒度过细，合并同层级相似节点或提升层级。 |
| 5WHY 推至第 5 层仍无突破 | 标注「未完全穿透」，以第 5 层结论作为当前最佳真问题继续。 |
| MEQS 中王牌和杠杆象限都为空 | 结论本身就是发现：不存在高杠杆切入点，需系统性干预。标注于综合层。 |
| MEQS < 3 | 问题可拆解度低，不适合以子问题形式解决。直接进入第五层给出系统性建议。 |
